# 0006 npm に出さず、コミットの SHA を指して使う

## 状況

- 使う側は、ワークフロー（再利用ワークフロー）・CLI・CDK のコンストラクトを、自分のリポジトリから使う

## 決めたこと

- npm には出さない。使う側は、このリポジトリのコミット（40 桁の SHA）を指す（ワークフローの `uses: ...@<SHA>` と `review_canvas_ref`、CLI・CDK は取り出したコミット）
- 依存は版をそのまま（exact）で書き、出てから 3 週間たった版だけを入れる（`pnpm-workspace.yaml` の `minimumReleaseAge`）。ワークフローの Action もコミットの SHA で固定する

## 結果

- 使う側が見ているコードと動くコードが、同じコミットになる
- 互換を崩す変更は、使う側が SHA を上げたときに効く。崩すものは README と docs に移し方を書く（[development.md](../development.md#リリースと互換性)）
- 版の番号・変更の履歴の配布は無い（コミットの履歴が履歴）
