# ブランチの Storybook を置く

1 つの配信（URL）に、ブランチごとの Storybook を置きます。画面の「ブランチ」で選ぶと、そのブランチの Storybook とコメントに入れ替わります。
置くのは手元の CLI（`review-canvas publish`）か、使う側のリポジトリから呼ぶワークフロー（`.github/workflows/publish.yml`）です。

## 置き場

| S3 のキー                                           | 中身                                                                                                                                                                                                                                                                                                                                                                                                 |
| --------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `sb/<ブランチのキー>/<id>/`                         | そのブランチの Storybook のビルド結果。`assets/`（名前にハッシュを持つ）を先に immutable で足し（消さない）、ほかを no-cache で入れ替え、橋渡し（`review-canvas-bridge.js`）と、橋渡しを差し込んだ `iframe.html`・`index.json` を続けて置き、目録を書いた後で古い `assets/` を消す（置いている途中に開いている画面が、消えたファイルを読みに行かないように）。途中で止まったときは置き直してください |
| `sb/<ブランチのキー>/<id>/review-canvas-shots/`     | 置くときに撮ったストーリーの画像（`<ストーリー ID>-<幅>-<中身のハッシュ>.png`。設定の `widths` の幅ごと・ページ全体の高さ）。名前に中身のハッシュを持つので immutable で足し、目録を書いた後で古いものを消す                                                                                                                                                                                         |
| `sb/<ブランチのキー>/<id>/review-canvas-shots.json` | 画像の目録 `{ version: 1, shots: [{ storyId, width, height, path, thumb?, transitions? }], playFunctions, transitions? }`（no-cache）。キャンバスはこれがあれば画像を並べ、無ければ（撮る前の版で置いた・撮れなかった）いままでどおり iframe で出す。比べる相手のブランチ（上の帯の「比較するブランチ」で選ぶ）の目録と画像の名前を比べて「変更」「新しい」を出す（どちらかに無ければ比べない）      |
| `sb/<ブランチのキー>/meta.json`                     | 目録 `{ version: 1, branch, commit, builtAt, storybooks }`。置くときは最後に書き、消すときは最初に消す（目録があれば中身は揃っている）                                                                                                                                                                                                                                                               |
| `index.html`・`assets/`・`app-config.json`          | キャンバスの画面（スタックが置く。どのブランチでも同じ）                                                                                                                                                                                                                                                                                                                                             |
| `sb/mockServiceWorker.js`                           | msw のサービスワーカー。Storybook 用の配信が `/mockServiceWorker.js`（オリジン直下でないと効かない）として返す。どのブランチでも同じものを読む。**既定のブランチを置くときだけ**、そのブランチのもので上書きする（オリジンの直下・scope `/` で動くので、ほかのブランチからは書けない）                                                                                                               |
| `mockServiceWorker.js`                              | 画面の配信の、自分を外すだけのサービスワーカー（スタックが置く）                                                                                                                                                                                                                                                                                                                                     |

- ブランチのキーは、ブランチ名の英数字と `.` `_` `-` をそのまま、ほかのバイト（`/`・`~`・日本語など）を UTF-8 の 1 バイトずつ `~XX`（大文字の 16 進）にしたものです。例: `main` → `main`、`claude/x-y` → `claude~2Fx-y`、`fix~1` → `fix~7E1`。逆に戻せ、別のブランチが同じキーになりません（`api/infrastructure/published-storybooks/branch-key.ts` と `infra/scripts/branch-key.ts`。同じ中身であることをテストで確かめる）
- API（`/api/meta`）は `sb/` の直下を一覧して各ブランチの `meta.json` を読み、ビルドした日時の新しい順に返します（30 秒ためてから読み直すため、置いてから画面の一覧に出るまで最大 30 秒ほどかかります）。目録の無い・壊れたもの（置いている途中・消している途中）は無いものとします。Lambda に許すのは `sb/` の直下の一覧と `sb/*/meta.json` の読み取りだけです
- 既定のブランチ（`REVIEW_CANVAS_DEFAULT_BRANCH`。既定は `main`）が置いてあればそれを、無ければいちばん新しく置いたブランチを開きます
- 置いたブランチのコメントのコミットは、そのブランチに置いてある Storybook のコミットです
- 1 ブランチあたりの大きさは Storybook のビルド結果の分です（`--test` のビルドにすると小さくなる）。S3 の保存は 1GB あたり月 0.025 USD ほどなので、10MB の Storybook を 50 ブランチ置いても月 0.02 USD 程度です。置くたびに Storybook 用の配信のキャッシュを 1 パス（`/sb/<キー>/*`。既定のブランチは `/mockServiceWorker.js` も）消します（キーの `~` は CloudFront が断るので `%7E` にして渡す。月 1,000 パスまでは無料）。置く・消すのは PUT・DELETE で 1 ブランチ 300 ファイルほど

## 手元から置く・消す

review-canvas を取り出した場所で `pnpm install` しておき、使う側のリポジトリの中から CLI を動かします（`bin/review-canvas.mjs`。`node <review-canvas>/bin/review-canvas.mjs` か、取り出した場所で `pnpm link --global` して `review-canvas` として呼ぶ）。

```bash
# いまのチェックアウトの Storybook を設定ファイルのとおりにビルドし、いまのブランチとして置く
review-canvas publish --profile <プロファイル>

# ブランチを消す（目録 → 中身 → キャッシュの順）
review-canvas unpublish <ブランチ> --profile <プロファイル>

# 置いてあるか（true/false）・置いてあるブランチの一覧（JSON）
review-canvas is-published <ブランチ> --profile <プロファイル>
review-canvas list --profile <プロファイル>
```

- 設定ファイルは `--config`（無ければ、動かした場所の git の根の `review-canvas.config.json`）、置くチェックアウトは `--repo-root`（無ければ動かした場所の git の根）です。ビルドのコマンドは設定ファイルのあるディレクトリで動かし、`outDir` もそこから解きます。`outDir` が `--repo-root` の外を指していたら止めます（絶対パス・`..` は設定の検証でも止める）
- 置き場（バケット・Storybook 用の配信の ID）と、橋渡しが受け付ける画面のオリジンは、`--bucket`・`--distribution-id`・`--canvas-origin`（または環境変数 `REVIEW_CANVAS_BUCKET`・`REVIEW_CANVAS_STORYBOOK_DISTRIBUTION_ID`・`REVIEW_CANVAS_CANVAS_ORIGIN`）が無ければ、スタック（`--stack-name`。既定 `ReviewCanvas`）の出力 `StorybookBucket`・`StorybookDistributionId`・`Url` から読みます
- 置くときは、橋渡し（`pnpm run build:bridge`）を review-canvas の版でビルドし、各 Storybook の `iframe.html` に差し込んでから置きます（元のビルド結果は書き換えない）
- 既定のブランチは、置くときはいつもスタックの出力 `DefaultBranch` を読みます。`--default-branch`（環境変数 `REVIEW_CANVAS_DEFAULT_BRANCH`）がそれと違えば止めます。共有のサービスワーカーは、このブランチを置くときだけ書きます
- `is-published` は目録（`meta.json`）を head-object で確かめます。発行用ロールの一覧（ListBucket）は `sb/` の下に絞っているため、無いキーが 404 ではなく 403 になることがあり、そのときは目録のキーを接頭辞にした一覧の件数で確かめ直します（一覧もできなければ失敗にする）
- `publish` は `--branch`・`--commit`（既定は Git のいまのブランチと短いコミット）・`--skip-build`（ビルド済みのものを置く）・`--dry-run`（AWS の操作を出すだけ）・`--region` を受けます。AWS の操作は AWS CLI（`aws`）で行うので、手元に入れておいてください
- ブランチ名は API が受け付ける形（英数字で始まる英数字と `._-/`、`..` なし、200 文字まで）だけを置けます
- 置くときは、ビルドのあとに全ストーリーのスクリーンショットを撮ります（`infra/scripts/story-screenshots.ts`。Playwright の Chromium で、ビルド結果を手元の `127.0.0.1` から配って開く）。設定の `widths` の幅ごとに、窓の高さを `baseHeight` にして開き、描画と play 関数が終わってから（Storybook の描画の段階が `completed`・`finished`・`errored` などになってから）、アニメーションを止めてページ全体を撮ります（16000px より長い画面はそこで切る）。並べて撮り（CPU の数まで。4 つまで）、描画の待ち・撮影のそれぞれを 30 秒で諦めます（メインスレッドを止めるストーリーも、外から時間で打ち切り、ページを作り直して次へ進む）。撮った後に遷移を読んでボタンを探すのも、合わせて 30 秒で諦めます（画像は置く）。全部の Storybook を合わせて 10 分を超えたらブラウザを閉じ、最初の 8 枚がすべて時間切れだったときも、残りを撮らずに、撮れた分だけの目録を書いて終えます。撮れなかったストーリーは目録に載らず、キャンバスが iframe で出します。目録には、画像のほかに、撮ったときの中身の高さと主な要素（押せる要素・見出し。1 枚 150 個まで）の位置・文字の先頭・その要素の見出し（前にあるいちばん近い見出しの文字の先頭）を残します（キャンバスが、画像の上でクリックした位置の要素が動く画面でも同じかを確かめるのに使う。入力欄の中身は残さない）。キャンバスは、押した点に主な要素があれば、動く画面の同じ位置の要素と種類・文字・見出しを比べ、高さは緩く（24px か 5% まで）比べます。主な要素が無い点では、高さを狭く（8px か 1% まで）比べます。撮ったときと見る端末でフォントが大きく違い、要素がその分動いた画面では「画面が変わりました」が出ます（動く画面でクリックし直すと置ける）。見出しを残す前に置いたブランチは、見出しを比べないだけで、そのまま動きます（置き直すと比べる）。ブラウザには AWS・GitHub Actions の環境変数（`AWS_*`・`ACTIONS_*`）を渡さず、配っている `127.0.0.1` の外への通信（HTTP・WebSocket）は止めます（外の画像・フォントは写りません）
- Chromium は `pnpm --dir infra exec playwright install chromium` で入れておきます。入っていない・撮れないときは、知らせを出して画像なしで置きます（置くこと自体は止めない）。`--skip-screenshots` を付けると撮らず、ビルド結果の中にすでにある画像と目録（`review-canvas-shots/`・`review-canvas-shots.json`）を確かめて置きます（無ければ画像なし）。`--shots-root <根>` を付けると、画像と目録をビルド結果の中ではなく、別の根の同じ場所から読んで置きます（撮らない。ワークフローが既定のブランチで使う）。撮るだけなら `pnpm --dir infra run screenshots --repo-root <dir> --config <file>` です
- 目録に残すのは、置き場（`review-canvas-shots/`）の直下にあり、リンクでなく、中身が PNG の行だけです。置く画像は、残した行が指す画像（元の画像と縮小）だけで、作業用の場所に写してから置きます（目録に無いファイルは、PNG でも置かない）
- 目録の遷移（使う側の書き方は [host-setup.md](host-setup.md#画面のつながり遷移を書く)）: `transitions` はストーリー ID ごとの行の並び `{ index, to, label? }`（`index` は書いた順の位置。0 から。書き方の違う行は残さず、位置は `index` で保つ）、`shots[].transitions` はその画像で見つかったボタンの矩形 `{ index, x, y, width, height }`（見つからない・複数に当たった・画像の外の行は入れない）です。どちらも無くてよい項目で、版は 1 のままです（古いキャンバスは無視し、新しいキャンバスは無ければ遷移なしとして読む）。目録を読むときは、知らない形の行を 1 行ずつ捨てます（`to` がストーリー ID の形でない・200 字を超える、`label` が 40 字を超える、矩形が画像の外、`index` が範囲の外・重なる、1 ストーリー 50 行を超える分）。`--skip-screenshots`・`--shots-root` で撮らずに置くときは、ストーリーを読み直さず、前の目録の遷移をこの確かめに通して置きます（書き間違いの一覧は出さない）
- 画像ごとに、幅・高さを 1/4 にした縮小（`…-thumb.png`。目録の `shots[].thumb`）も作ります。キャンバスは、引いて見るとき（画面上の大きさが縮小の大きさ以下）に縮小を出し、全体を見渡すときに原寸の画像を全部は読みません。縮小の無い目録（前の版で撮ったもの）は、いつも原寸を出します
- ビルドは Storybook の `--test` にするのがおすすめです（docs のアドオン・自動の docs・ソースマップを外す。画面ごとの iframe が DocsRenderer を読まなくなり、軽くなる）

## GitHub Actions から置く

使う側のリポジトリから、review-canvas の `.github/workflows/publish.yml` を `workflow_call` で呼びます（呼び方は [host-setup.md](host-setup.md#ワークフローから置く)）。

| きっかけ（呼ぶ側のイベント）  | すること                                                                                                                                                   |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 手で動かす（`branch` を指定） | そのブランチをチェックアウトして置く（空ならワークフローを動かしたブランチ）                                                                               |
| 手で動かす（`all` に印）      | いま置いてあるブランチを全部置き直す（2 つずつ。既定のブランチは除く）                                                                                     |
| どこかのブランチへの push     | そのブランチが置いてあり、設定ファイルの `watchPaths` が前の push から変わったときだけ置き直す（`publish_unpublished_on_push` なら、置いていなくても置く） |
| ブランチを消した              | 置いてあれば消す                                                                                                                                           |

- 置いていないブランチは push しても置きません。置くかどうかは、はじめに手で決めます（手で動かすか、手元の `review-canvas publish`）。`publish_unpublished_on_push` を付けたときは、置いていないブランチも push で置きます（`watchPaths` が変わったとき。新しいブランチは変わったとみなす）
- 同じブランチの置く・消すは並べず、順に動かします（途中で止めると置き場が半端になるため、途中のものは止めない）
- `role_arn` が空で `roles_from_secrets` でもなければ、どのジョブも動かさずに終わります。既定のブランチを置くときに `main_role_arn` が空なら、その置く処理は失敗します
- 置く手順（スクリプト・橋渡し）は、`review_canvas_ref`（40 桁のコミットの SHA。`uses:` の `@` と同じにする）の review-canvas から取り出します。SHA でなければ止めます
- ビルドと置くことはジョブを分けます。置くブランチは `host/` へ取り出して、AWS の資格情報を持たないジョブ（`build`。`id-token` なし）で Storybook をビルドし、成果物にします。AWS の資格情報を持つジョブ（`publish`）は、橋渡しを review-canvas のコミットから自分でビルドし（成果物の中のものは使わない）、成果物を review-canvas のスクリプトで置くだけで、置くブランチのコードは動かしません（`review_canvas_ref` を置くブランチと同じコミットにした呼び方〈このリポジトリの `storybook.yml`〉では、そのブランチの置くスクリプトが動きます。[security.md](security.md#置くときの守り)）
- スクリーンショットも `build` のジョブで撮ります（置くブランチのストーリーをブラウザで動かすので、AWS の資格情報を持たない側で）。撮る手順は `review_canvas_ref` の review-canvas のもので、Chromium はそのジョブで入れます（`playwright install --with-deps --only-shell chromium`）。入らない・撮れない・時間切れ（Chromium を入れる step は 8 分、撮る step は 12 分）でもジョブは続き、画像なしで置きます。依存を入れる step は 10 分、Storybook をビルドする step は 20 分までで、ジョブの上限（60 分）は step の上限の合計より長くしてあります（撮影の時間切れで、ジョブごと落ちない）。`publish` のジョブは成果物の画像を確かめて置くだけで、どのブランチでもブラウザを動かしません（`--skip-screenshots`）
- 既定のブランチのビルド結果は成果物を使わず、`publish` のジョブが既定のブランチのチェックアウト（Environment で既定のブランチからだけ動く。動かしたブランチが既定のブランチでなければ止める）から自分でビルドして置きます（ほかのブランチのビルドが、既定のブランチ向けのビルド結果を上げても使われない）。スクリーンショットだけは、既定のブランチも `build` のジョブで撮り、画像と目録だけを成果物にして、`publish` のジョブが確かめて置きます（`--shots-root`。成果物から使うのは、中身が PNG の画像と形の合う目録だけ。`build` のジョブでの既定のブランチのビルド・撮影が失敗しても、画像なしで置く。手で動かしたときも、`build` のジョブは `publish` のジョブと同じコミットを取り出すので、画像とビルド結果のコミットはそろう）。`all` で置き直すときも既定のブランチは外すので、既定のブランチは既定のブランチへの push か、既定のブランチから手で動かして置き直します
- 成果物の設定ファイルの `id`・`outDir` は、ビルドのジョブ（シェル）と置くスクリプト（zod）の両方で形を確かめます
- 置いてあるか・目録の一覧の答えは形を確かめ（`true`/`false`・文字列の JSON の配列）、形が違えば失敗にします。シェルは `pipefail` で動かします。ブランチを消したときは、置いてあるかを見ずに消します（置いていなければ何もしない）
- AWS につなぐジョブだけが OIDC のトークン（`id-token: write`）を持ちます。使うアクションはコミットの SHA で固定しています。認証情報を扱うジョブでは pnpm のキャッシュを使いません
- push で動くのは、push したブランチにある呼ぶ側のワークフローのファイルです。ブランチの削除と、手で動かすときの既定（Use workflow from）は既定のブランチにあるファイルで動くため、既定のブランチに入るまではブランチを消しても Storybook は消えません（手元の `review-canvas unpublish` で消す）
- 既定のブランチは 1 つの値で決めます。スタックの `REVIEW_CANVAS_DEFAULT_BRANCH`（出力 `DefaultBranch`）と同じ値を `default_branch` に渡してください（空ならリポジトリの既定のブランチ）。食い違えば、置くスクリプトが止めます
- ロール・Environment の分け方と、ロールに許すことは [github-aws-permissions.md](github-aws-permissions.md) にあります
