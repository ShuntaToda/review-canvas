# 設計メモ: コメントにスクリーンショットを残す

**コメントに結び付ける部分は、まだ作っていません**（置くときに全ストーリーの画像を撮り、キャンバスに並べる部分は作ってあります。[publishing.md](publishing.md)）。作るときの考えどころをまとめたメモです（決めるのは人。ここに書いた形は案です）。

## ねらい

- コメントを書いたときの見た目を残す。Storybook を置き直して画面が変わっても、「何を見て書いたか」が分かる
- AI が直す場所を特定する手がかりを増やす（いまは `anchor` の文字の手がかりだけ。[api.md](api.md#要素の手がかりanchor)）
- AI が直したあとの見た目と、書いたときの見た目を人が見比べられる（「確認待ち」を確かめやすくする）

## 前提（いまのしくみから来る制約）

- キャンバスと Storybook は別のオリジンです（[security.md](security.md)）。キャンバスの側から iframe の中の絵は読めません。撮れるのは、iframe の中の橋渡し（`src/features/review/bridge/`）か、ブラウザの外（ヘッドレスのブラウザ）だけです
- 橋渡しは、ブランチごとに誰でも置き換えられるコードと同じオリジンで動きます。橋渡しから届くものは信頼しない、がいまの決まりです（形と大きさをキャンバスと API の両方で確かめる）。画像も同じ扱いにします
- コメントは DynamoDB の 1 項目です（400KB まで）。画像そのものは入れられません
- 入力欄に入れた値は `anchor` に残さない決まりです。スクリーンショットは、この決まりをそのままでは守れません（画面に出ているものは写る）

## 撮り方の案

| 案                                            | 撮るところ                               | よいところ                                             | 気になるところ                                                                                                             |
| --------------------------------------------- | ---------------------------------------- | ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------- |
| A. 橋渡しが DOM を画像にする                  | iframe の中（DOM を SVG 経由で描き直す） | 書いた人が見ている状態（操作したあと）をそのまま撮れる | 描き直しなので本物と少しずれる（フォント・別オリジンの画像・canvas）。橋渡しが大きくなる。信頼しない側が作る画像を受け取る |
| B. ブラウザの画面共有（`getDisplayMedia`）    | キャンバスの側                           | 本物の絵                                               | 毎回、共有の許可が要る。ほかのタブ・通知まで写りうる。レビューの流れを止める                                               |
| C. 置くときにヘッドレスのブラウザで撮っておく | CI（publish の前の build ジョブ）        | 本物の絵。信頼できる側が撮る。コメントの外で 1 回      | 撮れるのは最初の状態だけ（操作したあとは撮れない）。ビルドが長くなる。play 関数・幅ごとに枚数が増える                      |

**すすめる順**: まず C（ストーリーごと・幅ごとに 1 枚を、置くときに撮って S3 に並べる）。コメントは「そのコミットの、そのストーリーの絵」と「絵の上の位置（いま持っている割合）」を指すだけで済み、信頼の境目を増やしません。操作したあとの状態も要ると分かったら、A を足します。B は採りません。

## 置き場と API（C の場合）

> キャンバスを軽くするための画像（置くときに全ストーリーを撮り、`sb/<ブランチのキー>/<id>/review-canvas-shots/` に置く。[publishing.md](publishing.md)）は、もう作ってあります。撮る手順（`infra/scripts/story-screenshots.ts`）は C と同じですが、あちらはブランチを置き直すと入れ替わる「いまの絵」で、コメントには結び付けていません。下は、コメントに絵を残すために足すものです。

- 置き場: `sb/<ブランチ>/<id>/` の下ではなく、コミットごとの場所に置く（例: `shots/<id>/<コミット>/<ストーリー ID>/<幅>.png`）。ブランチを置き直しても、古いコメントが指す絵が残るように
- 目録: 置くスクリプトが、撮れたストーリーと幅を目録（JSON）に書く。API は目録を読んで、スレッドに絵の URL（`links.screenshot`）を足す
- 配るところ: Storybook 用のオリジンではなく、キャンバスのオリジンの下（ログインした人だけが読める道）で配る。`Content-Type` を画像に固定し、`nosniff` を付ける
- 片付け: ブランチを消しても絵は残すので、S3 のライフサイクル（日数）で消す。日数は設定で受ける
- コメントの項目は足さない（コミット・ストーリー ID・幅・位置はもう持っている）。互換を崩さない

## A を足す場合に守ること

- 橋渡しは画像（PNG か WebP）を作り、キャンバスへ `postMessage` で渡す。キャンバスは種類・大きさ（例: 1MB・長辺 4000px まで）を確かめ、署名つきの URL で S3 へ直接上げる（API の Lambda を通さない）
- 署名つきの URL は、ログインした人に、コメント 1 件につき 1 枚、短い期限・大きさの上限・`Content-Type` 固定で出す。上げた絵のキーをコメントに残し、書いた人（`authorId`）と結び付ける
- 絵は描き直して（デコードして再エンコード）から配るか、少なくとも `Content-Disposition`・`nosniff`・画像だけの `Content-Type` で配る。SVG は受け取らない
- 入力欄の値は、撮る前に橋渡しが伏せる（`input`・`textarea`・`contenteditable` を塗りつぶす）。伏せきれないもの（画面に出した個人の情報など）があることを、書く人に見える形で知らせ、付ける・付けないを選べるようにする

## AI への渡し方

- `GET /api/threads` のスレッドに絵の URL を足し、MCP の `get_comment` は、絵を画像の中身（MCP の `image`）として返す（URL を渡しても、AI はログインが要る絵を読めないため）
- 絵は大きいので、`list_open_comments` には入れない（1 件を読むときだけ）
- AI が直したあとの絵は、次に置いたときの C の絵（新しいコミット）がそのまま使える。画面は「書いたとき」と「いま」を並べて出す

## 決めること（作る前に）

- 絵に写るものの扱い（サンプルではないデータを Storybook に出しているチームがあるか。伏せる範囲）
- 残す期間（既定の日数）と、置き場の費用の見積もり
- C で撮る幅（設定の `widths` のすべてか、`defaultWidth` だけか）と、ビルドの時間の上限
- ヘッドレスのブラウザをどのジョブで動かすか（資格情報の無い build ジョブで撮り、成果物として渡す。AWS を使うジョブではブラウザを動かさない）
